# 官方插件下载与统计

服务源码位于 `apps/server`，与 `apps/desktop` 同级。

## 下载链路

官方插件统一使用：

`App → HTTPS 统计下载 API → 302 → COS → 客户端完整性校验 → SQLite 回报队列 → 成功确认 API → MySQL`

- 插件索引：`https://plugins.toolforge.devlive.org/registry.json`。
- 统计 API：`https://stats.toolforge.devlive.org`，需要配置独立 DNS 与 TLS。
- 文件桶：`toolforge-1258585472`，当前 CNAME 指向新加坡 COS，发布前核实地域配置。
- `registry.json` 中 `url` 是统计下载 API 地址，不是 COS 文件直链。
- App 市场首次安装、更新和官网 `toolforge://plugin/install/...` 深链共用 Rust 下载层。
- App 不会在统计下载服务失败时静默改走 COS；用户可以重试。
- 浏览索引、打开已安装插件、本地导入、官网按钮点击均不增加成功下载数。
- 本地文件和第三方插件不进入官方统计；原有用户信任确认流程继续有效。

## 统计口径

下载量为客户端完整下载并通过大小、SHA-256、官方签名、插件 ID 与版本校验后确认的次数。它不等于设备数、安装量、活跃用户数或 COS 实际字节传输次数。

完整验证后即产生回报；之后安装或 WASM 启用失败，不撤销这次下载。当前插件更新流程不保证恢复旧插件目录，不能把服务端二进制回滚理解成插件安装回滚。

- 同次下载网络重试复用 attempt ID。
- 同次成功回报重复发送只增加一次。
- 用户以后重新发起一次实际下载可以再次计数。
- 旧客户端会自动跟随 302，但不会读取回报凭据，因此只能记录发起次数。
- 新口径从统计服务启用开始累计；不将 GitHub 资产下载数混入成功下载量。
- 公开客户端可以被修改，不能以成功回报作为防作弊证明。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /v1/plugins/{id}/versions/{version}/download` | 创建或复用一次下载尝试，302 到受信 COS 对象 |
| `POST /v1/downloads/{attempt_id}/complete` | 幂等确认成功 |
| `GET /v1/plugins/{id}/versions/{version}/stats` | 指定版本下载量及插件累计量 |
| `GET /v1/plugins/{id}/stats?limit=50&offset=0` | 插件累计量和分页历史版本 |
| `GET /v1/stats?ids=id1,id2` | 最多 100 个插件的批量统计 |
| `GET /v1/stats/total` | 所有官方插件累计量 |
| `GET /healthz` | 进程健康与 buildSha |
| `GET /readyz` | 数据库/schema 就绪与 buildSha |

新客户端发送 32 位小写十六进制 `Idempotency-Key`。302 响应为 `Cache-Control: no-store`，包含：

- `Location`：受信 COS HTTPS 地址。
- `X-ToolForge-Attempt-Id`：本次尝试 ID。
- `X-ToolForge-Receipt`：只允许发送给确认 API 的临时凭据。
- `X-ToolForge-Receipt-Expires`：Unix 秒到期时间。

客户端关闭第一跳自动重定向，读取这些字段后单独向 COS 下载，不转发凭据。确认请求使用 `Authorization: Bearer`，JSON 包含 `sha256`、`size`。任何日志、错误详情或 URL 都不得包含凭据。

查询计数是十进制字符串，前端以 BigInt 格式化，避免超过 JavaScript 安全整数范围丢失精度。失败和缺失值显示“暂不可用”，合法零值才显示 0。批量查询可能截断单插件版本列表，完整历史使用分页接口。

## 数据持久化与幂等

MySQL 独立库保存官方全版本目录、下载尝试、每版本及插件累计量、目录代次和迁移状态。

成功确认在一个 InnoDB 事务中锁定 attempt，再将 issued 状态变成 confirmed，同时原子增加版本和插件计数；重复请求不再增加。相同 attempt 绑定不同版本或制品返回冲突，未知 attempt 不能直接计数。

官方目录只由受限发布入口导入，不提供公网管理写 API。每个插件版本的 SHA、大小和 object key 不可更换；普通下架停止新下载但保留已签发回报和历史计数，安全撤销单独处理。

App 回报队列使用已有 SQLite，应用重启后可续报；网络/5xx/429 按退避重试，永久性错误结束；回报和队列故障不阻塞插件安装。回报有效期 7 天，本地最长保留 5 天，并始终受凭据实际到期时间约束。

尝试记录有保留与清理策略，累计计数长期保留。备份必须同时覆盖计数和幂等记录；不能期望从短期明细重建全部历史。

## 插件发布

1. 在受信分支检查版本和历史目录；读取失败不能当作空历史。
2. 不带发布秘密构建候选包。
3. 独立签名步骤使用现有 Ed25519 私钥；构建子进程不可继承私钥。
4. 生成最新版本 registry 和全版本 release-catalog。
5. 上传不可变 COS 包，以 SHA 作为对象路径组成部分。
6. 通过内容域名读回验证大小和 SHA，不能把 ETag 当作 SHA。
7. 保存不可变目录和索引快照，导入统计服务版本目录。
8. 最后更新公共 registry，再更新 GitHub 兼容镜像。

任何阶段失败均不能覆盖已发布同版本制品；中间产生的未曝光对象保留供重试对账。COS 与 MySQL 不存在跨系统原子事务，registry 是面向客户端的最终发布点。

一次性历史迁移使用 GitHub 原始签名包，不重新构建、不重新签名、不导入旧下载数。缺失、签名异常或同版本内容冲突必须停止处理。

## 部署与配置

Go 服务在 CI 编译 Linux amd64 单二进制，服务器不需要 Go。通过 systemd 专用低权限用户运行，只监听 `127.0.0.1:8088`，由现有 Nginx 的独立站点提供 HTTPS。

生产 MySQL 使用本机 `/var/run/mysqld/mysqld.sock` 与专用账号，不假设 TCP 3306。现有服务器数据库监听和业务配置不由此功能修改。

配置、首次初始化和受限部署步骤见仓库的服务 README 与部署 README。运行、迁移、目录导入使用独立数据库权限。MySQL 密码和 receipt HMAC keyring 只保存在服务器受限配置中；客户端和 GitHub 构建任务不持有它们。

GitHub 需配置：

- 现有插件签名 Secret。
- 仅目标桶和必要对象前缀权限的 COS 凭据，优先短期凭据。
- 独立服务部署、目录导入 SSH 身份与已核验的 known_hosts。
- 桶、地域、内容域名、API 域名等普通 Variables。
- 受信发布分支和生产 Environment；不可信 PR 不获得发布秘密。

禁止将密码通过命令行参数、工作流正文、制品或聊天传递。配置示例仅提供变量说明，不含真实值。

## 回滚

- 服务发布：制品校验、服务端部署锁、向前兼容迁移、切换 current、重启、核对 readyz 与新 buildSha；失败恢复旧链接并重启。
- 数据库：DDL 存在隐式提交，不承诺失败自动事务回滚；生产不自动执行 down 或删除累计计数。
- 插件索引：恢复已验证的历史索引快照，不覆盖或删除不可变插件包。
- 数据恢复：一致备份计数与幂等状态，明确恢复点之后可能少计，不伪造补数。

## 验证

自动检查覆盖：同一 attempt 并发确认只计一次、事务失败、确认响应丢失重试、密钥轮换、过期和重放、错误制品、URL 白名单、两下载入口、SQLite 重启续报、大整数展示及统计失败状态。CI 的 MySQL 8.0 集成测试使用隔离测试凭据，不接生产数据库。

上线前还需：核验 MySQL 专用账号与备份、确认 COS 地域/对象读取权限、配置 API DNS/TLS、固定 SSH 主机身份、准备生产 Secrets。代码实现完成不表示生产已部署或统计已经开始。
